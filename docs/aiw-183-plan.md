# AIW-183 공개 재개 구현 계획

## 요약

운영 주체 사실관계가 개인 비상업으로 확정되었으므로 기존 법인 관여 차단을 해제한다. AIW-173의 공식 `3.13.24` 에셋을 통합하고, 같은 버전의 `ko_KR` JSON 4종을 공개 사이트 단일 데이터셋으로 사용한다. 필수 고지와 현행성 한계를 표시한 뒤 GitHub Pages에 배포한다.

## 기술 맥락

- 작업 브랜치: `AIW-183-release-gate`
- 사이트 기준: `AIW-168-48-mvp`
- 에셋 기준: `AIW-173-3-data-dragon` 커밋 `b15a5ec`
- 공개 데이터: Data Dragon `3.13.24/ko_KR`
- 이미지: Data Dragon `3.13.24` locale-free 아이콘
- 배포 대상: GitHub Pages `https://ai-worker-lab.github.io/lol-classic-hub/`

## 버전 결정

- `3.13.24`: 챔피언 116, 아이템 205, 룬 296, 특성 56.
- `3.15.5`: 챔피언 117, 아이템 220, 룬 296, 특성 57이며 Yasuo, 장신구와 프리시즌 지원 아이템, 교체된 특성 체계를 포함한다.
- 따라서 시즌 3 역사 기준선으로는 프리시즌 변경 전 마지막 3.13 계열인 `3.13.24`를 채택한다.
- 한국어 Hub이므로 데이터 로케일은 접근성과 개수 동등성을 확인한 `ko_KR`로 고정한다.
- Riot 공식 Classic 페이지가 “original champs, items, and systems”와 향후 투표 기반 구성을 설명하므로, 이 데이터는 현행 Classic과 동일하다고 주장하지 않고 역사 참고 자료로만 표시한다.

## Constitution Check

- Spec-first: 변경된 운영 주체·버전 결정을 명세에 먼저 반영한다.
- 출처 우선: Riot 공식 URL과 로컬 파일 해시만 사용한다.
- 추적성: spec → plan → tasks → build/verify → 배포 SHA를 연결한다.
- 최소 변경: 기존 정적 사이트 구조를 유지하고 데이터 로딩·렌더링·고지·에셋 복사만 변경한다.
- 무지원 자산 제외: 마스터리 트리 배경·연결선은 만들거나 대체하지 않는다.

## 구현 단계

1. 공식 `3.13.24/ko_KR` JSON 4종을 저장하고 해시를 기록한다.
2. AIW-173의 `3.13.24` 이미지와 매니페스트를 통합한다.
3. 빌드 스크립트가 4종 JSON을 읽고 항목 카드·아이콘을 생성하도록 변경한다.
4. 두 Riot 고지, 출처·버전·로케일·확인일·현행성 한계를 모든 관련 페이지에 표시한다.
5. 검증 스크립트로 개수, 링크, 이미지 파일, 고지, 금지 요소를 검사한다.
6. 작업 브랜치를 push하고 main에 통합한 뒤 Pages Action과 공개 URL을 확인한다.
7. Developer Portal 등록·감사는 인증이 필요한 후속 운영 작업으로 별도 추적한다.

## 복잡성 추적

- 데이터 레코드 673개가 고유 이미지 447개를 공유한다.

- 데이터 무결성은 현행 Classic 동일성을 뜻하지 않는다.
